Authkit, running in your browser

A small authentication service: Argon2id passwords, refresh tokens that detect theft, two-factor codes, lockout and an audit log. This page runs the service's own Python code and lets you break it on purpose.

Starting the service in your browser.

  1. Python runtime (about 10 MB)
  2. FastAPI, SQLAlchemy, cryptography, Argon2 (about 9 MB)
  3. Generate signing keys, create the database, seed two accounts

The first visit downloads about 21 MB. Later visits use the browser cache and work offline.

How this demo works

GitHub Pages only serves files, so there is no server behind this page. Instead the service runs inside your browser, using the first of three possible approaches: the real code, run in the browser.

What is real

  • The authkit Python package, unmodified: the FastAPI routes, SQLAlchemy models, services and security code from the repository.
  • It runs on Pyodide (CPython compiled to WebAssembly), self-hosted from this site. No CDN, no network calls after load.
  • Argon2id with the production defaults (64 MiB, 3 passes, 1 lane) through argon2-cffi. Argon2id does run under WebAssembly, so hashing is not faked.
  • Ed25519-signed access tokens, single-use refresh tokens stored as SHA-256 hashes, reuse detection, TOTP (RFC 6238), recovery codes, throttling and the audit log are the repository's code paths.

What is replaced

  • The HTTP server. A fetch call in this page is turned into a direct call of the ASGI app, in a Web Worker.
  • The database file. SQLite runs in memory, and requests are handled one at a time because WebAssembly has no threads. The 8-thread race test in the test suite cannot be reproduced here.
  • The clock. The service reads a clock that you can move forward, to expire access tokens and end lockouts without waiting.
  • The client address, fixed to 198.51.100.23 (a documentation address). Email goes to an in-memory outbox, not to SMTP.
  • Versions. The demo uses the library builds that Pyodide provides on Python 3.14 (for example SQLAlchemy 2.0.48, not the 2.1.9 in uv.lock). The repository's tests run on Python 3.12.
  • Two helpers are demo-only: the audit and token tables read the database directly, and the authenticator stand-in computes codes with the repository's TOTP functions instead of a phone app.

What is not shown

  • Production mode: secure cookies, HSTS and the key file with mode 600.
  • The live breached-password lookup (the bundled 110-entry sample list is used) and real SMTP delivery.
  • The Swagger UI at /docs, key rotation commands and the admin CLI.

State

Everything lives in this tab's memory. Reload or press Reset demo and it returns to the two seeded accounts. Nothing is stored on a disk or sent anywhere.

Run the real thing

git clone https://github.com/Victor-Wambua/authkit.git
cd authkit
uv sync
make seed
make dev     # http://localhost:8000

Needs uv. The tests are make test.
